프로그램, 프로세스, 스레드를 간단히 정리하고 멀티스레드를 알아봅시다.

구조
```
프로그램 파일을 실행하면 프로세스
프로세스 내부에서 스레드가 생성

프로그램
  ↓ 실행
프로세스
  ├── 스레드 1
  ├── 스레드 2
  └── 스레드 3
```

# 프로그램
디스크에 저장된 실행 파일. 아직 실행되지 않은 상태의 코드와 데이터.

# 프로세스
프로그램을 실행하면 프로세스가 됨.(실행 중인 프로그램)
프로세스는 운영체제로부터 다음 자원을 할당받음. 
메모리, 파일, 네트워크 연결, 실행 권한, 프로세스 ID

프로세스끼리는 기본적으로 메모리가 분리됨.

# 스레드
프로세스 안에서 실제 작업을 수행하는 실행 단위.
하나의 프로세스는 최소 하나의 스레드를 가짐.
동 프로세스 내 스레드들은 메모리 일부를 공유.

예를 들어 음악 앱 프로세스가 있다면 그 안에는 음악 재생 스레드, 화면 표시 스레드, 네트워크 통신 스레드 등이 존재.

## 싱글스레드
스레드가 하나라면 음악 재생, 화면 갱신, 네트워크 통신 등 여러 작업 수행 시 하나의 작업이 오래 걸리면 뒤의 작업이 기다려야 함. (네트워크 통신이 오래 걸리면 앱 화면이 멈춤)

## 멀티스레드
스레드가 여러 개라면 스레드별로 작업을 처리하므로 한 작업이 오래 걸려도 다른 작업은 계속 수행됨. 


### 멀티스레드의 특징
- 응답 속도가 빨라짐.
- 자원 활용이 효율적.(프로세스 내 메모리 공유)
- 동기화 문제 (여러 스레드가 메모리를 일부 공유하기 때문에 공유 데이터를 안전하게 관리해야 함.)
- 교착상태 deadlock (여러 실행 흐름이 서로가 가진 자원을 기다리느라 영원히 멈추는 상태)
