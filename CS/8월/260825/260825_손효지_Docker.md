# Docker

## 1. Docker란?
1) 애플리케이션을 코드, 런타임, 시스템도구, 라이브러리 등 실행에 필요한 모든 환경과 함께 `컨테이너`라는 독립된 단위로 Packaging 해주는 오픈소스 가상화 플랫픔 &rarr; `내 컴퓨터에서는 됐는데?` 해결 가능

2) 이미지와 컨테이너\
(1) 이미지: 레시피(설계도). 프로그램을 실행할 때 필요한 모든 재료와 순서가 적힌 고정된 `설계도`임.\
(2) 컨테이너: 레시피로 요리된 음식(실행박스). 설계도는 그대로 두고 여러 컨테이너를 동시에 생성할 수도 있음.

## 2. 핵심 키워드
1) 이미지: 프로그램 실행에 필요한 파일과 설정이 담긴 **읽기 전용 파일**.
2) 컨테이너: 이미지를 실행해 메모리상에서 독립적으로 동작하고 있는 프로세스.
3) Dockerfile: 이미지를 만들기 위해 어떤 os를 사용하고 어떤 패키지를 설치할지 순서대로 적어둔 설명서. 텍스트 파일 형태.
4) 볼륨: 컨테이너가 삭제돼도 데이터가 날아가지 않게, 컨테이너 내부 데이터를 호스트 컴퓨터의 물리 디스크와 연결해주는 기능.
5) 포트 포워딩(Port Forwarding): 격리된 컨테이너 내부로 외부 사용자가 접속할 수 있도록, **내 컴퓨터의 포트와 컨테이너의 포트를 연결**해주는 설정. `-p` 옵션.
6) Docker Compose: 웹서버, 데이터베이스 등 여러 개의 컨테이너를 하나의 파일로 정의하고 한 번에 묶어서 관리 및 실행하는 도구.

## 3. 개발자에게 Docker의 존재 의미
1) `내 컴퓨터에선 되는데`라는 핑계 없애줌: 운영체제, 라이브러리 버전 차이로 발생하는 환경 충돌을 차단해서 개발 환경과 실제 서비스 환경을 일치시킨다.
2) 복잡한 환경 세팅을 빠르게 끝내줌: 복잡한 데이터베이스나 프레임워크를 내 컴퓨터에 매번 설치하고 설정하다가 지치는데, `docker run` 한 줄로 깔끔하게 띄우고 지울 수 있음.
3) 프로젝트 간 충돌 막아주는 벽: 여러 프로젝트 동시 진행 시, 각각 독립된 컨테이너에서 작업하기 때문에 서로 다른 버전의 프로그램이 꼬이거나 충돌하는 문제를 해결함.
