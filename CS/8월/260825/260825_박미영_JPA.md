## JPA (Java Persistence API)

```mermaid
**flowchart LR
    A["Java 객체"] --> B["EntityManager"]
    B --> C["영속성 컨텍스트"]
    C --> D["데이터베이스"]**
```

- **영속성 컨텍스트의 기능**
    1. **1차 캐시**
        - 한 번 조회한 엔티티를 영속성 컨텍스트에 보관
        - 같은 트랜잭션 안에서 반복 조회할 때 불필요한 DB 접근을 줄일 수 있음.
    2. **동일성 보장**
        - 같은 영속성 컨텍스트에서 동일한 ID의 엔티티를 조회하면 같은 객체를 반환
        - 데이터베이스의 같은 데이터를 나타내는 객체가 여러 개 생성되지 않도록 동일성 보장
    3. **변경 감지**
        - 영속 상태의 엔티티 값을 변경하면 JPA가 이를 감지
        - 별도의 update 메서드를 호출하지 않아도 트랜잭션이 끝날 때 SQL이 알아서 생성됨.

### 9. JPQL

- 지금까지는 기본 키를 이용한 단순한 조회
- 그렇다면 이름이나 나이처럼 특정 조건에 해당하는 회원을 조회하려면 어떻게 해야 할까?
- 이때 사용하는 게 JPQL

- **JPQL**
    
    > **테이블이 아니라 엔티티를 대상으로 데이터를 조회하는 객체지향 쿼리 언어**
    > 

```java
String jpql =
    "SELECT m FROM Member m WHERE m.age >= 20";

List<Member> members =
    entityManager.createQuery(jpql, Member.class)
                 .getResultList();
```

- JPQL은 `Member` 엔티티와 `age`필드를 대상으로 작성함.
- Hibernate가 JPQL을 실제 SQL로 변환함.

```java
SELECT *
FROM member
WHERE age >= 20;
```

### 10. JPA 사용 시 주의점

- 그렇다면 JPA를 사용하면 SQL을 몰라도 되는 것인가?
- JPA 내부에서도 결국 SQL이 실행됨
- JPA가 생성하는 SQL을 확인해야 함
- 연관관계를 잘못 사용하면 불필요한 SQL이 많이 실행될 수 있음
- 대표적인 성능 문제가 N+1 문제임
    - **N+1 문제**
        
        > **연관된 엔티티를 조회할 때 최초 조회 SQL 1번과 조회 결과 수만큼 추가 SQL N번이 실행되는 문제**
        > 
    - 예를 들어 회원 N명을 한 번에 조회한 뒤 각 회원의 주문을 확인하면 회원 조회 SQL 1번과 주문 조회 SQL N번이 실행될 수 있는데, 이를 N+1 문제라고 함.
    - 따라서 JPA를 사용할 때는 생성되는 SQL을 반드시 확인해야 함.
