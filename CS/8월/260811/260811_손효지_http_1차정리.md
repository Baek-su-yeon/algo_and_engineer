# HTTP와 HTTPS 개념 정리

## 1. HTTP - HyperText Transfer Protocol

- 정의: 웹 브라우저와 웹 서버가 HTML 등의 문서를 주고 받기 위해 사용하는 기본 통신 규약
- 전송 방식: 데이터를 Plain Text 평문에 그대로 전송
- 취약점: 네트워크 중간에서 트래픽을 가로채는 Sniffing 공격에 노출될 경우, 아이디나 비밀번호 등 민감 정보가 그대로 탈취될 수 있음
- 기본 포트: `80`번


## 2. HTTPS(HyperText Transfer Protocol Secure)

- 정의: HTTP 프로토콜에 보안 계층을 추가해 데이터 전송의 안전성을 확보한 통신 규약
- 보안 기술: SSL/TLS 인증서를 활용해 클라이언트와 서버 간 주고 받는 모든 데이터를 암호화함
- 핵심 기능;
  - 기밀성: 데이터를 가로채도 암호화돼있어 내용 해독 불가
  - 무결성: 전송 과정에서 데이터가 임의로 조작됐는지 감지 가능
  - 인증: 공인된 인증기관(CA)을 통해 해당 웹 사이트가 신뢰할 수 있는 곳인지 증명해 피싱 방지
- 기본 포트: `443`번

## 참고사항

### 1. 포트

- 정의: 컴퓨터(서버)가 외부 네트워크로부터 데이터를 주고 받을 때, 어떤 프로그램이나 서비스가 데이터를 처리해야하는지 구분해주는 논리적인 주소이자 통로.
- IP 주소와의 비유
  - IP 주소가 편지를 받을 수 있는 아파트 단지의 주소 혹은 건물 위치라고 가정
  - 포트는 그 아파트 안에서 찾아가야 할 호실 번호.
- 하나의 컴퓨터 서버 안에서 웹 서버, 이메일 서버, 파일 전송 서버 등 여러 프로그램이 동시에 실행될 수 있음. 이 때 외부에서 데이터가 들어왔을 때, 컴퓨터가 이 데이터를 어떤 프로그램으로 전달해야 할지 알려주는 식별번호가 **포트 번호**.

[포트 번호 예시]


| 포트 번호 | 서비스 이름 | 설명 |
| :--- | :--- | :--- |
| 80 | HTTP | 암호화되지 않은 웹 통신이 기본적으로 드나드는 통로 |
| 443 | HTTPS | 보안(SSL/TLS)이 적용된 웹 통신이 드나드는 통로 |
| 21 | FTP | 파일 전송용 통로 |
| 22 | SSH | 원격 접속 및 안전한 제어(Secure Shell)용 통로 |
| 3306 | MySQL | MySQL 데이터베이스와 통신하는 통로 |
