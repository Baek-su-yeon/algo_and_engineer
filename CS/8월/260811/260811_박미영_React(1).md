### React란?

- 사용자 인터페이스(UI)를 구축하기 위한 JavaScript 기반의 오픈소스 라이브러리
- Meta에서 개발
- 웹 화면을 독립적이고 재사용 가능한 컴포넌트 단위로 구성
- React에서는 현재 데이터에 따라 화면이 어떻게 보여야 하는지를 선언.
이후 데이터나 상태가 변경되면 React가 컴포넌트를 다시 렌더링하고, 변경이 필요한 내용을 실제 화면에 반영

### 2. React의 기본 동작

- React에서는 현재 데이터에 따라 화면이 어떻게 보여야 하는지를 작성
- 데이터가 변경되면 React가 이를 감지하여 새로운 데이터에 맞게 화면을 다시 그림.
- 데이터 변경 → 컴포넌트 다시 렌더링 → 변경된 화면 반영

### 3. 라이브러리인 이유

- React는 웹 애플리케이션에 필요한 모든 기능을 제공하지 않고 UI 구현에 집중
- 라우팅, 서버 통신, 전역 상태 관리 등의 기능은 필요에 따라 다른 라이브러리를 추가해서 사용

### 4. React는 왜 등장했을까?

1. **웹페이지가 복잡해짐.**
    - 초기의 웹은 문서와 정보를 보여주는 단순한 형태가 많았음.
    - 그러나 웹에서 좋아요와 댓글, 실시간 알림, 검색 결과 변경 등의 기능을 제공하면서 화면이 복잡해짐.
    - **즉, 데이터가 바뀔 때마다 화면도 함께 변경해야 하는 상황이 많아짐.**
2. **기존 JavaScript의 화면 변경 방식**
    - JavaScript에서는 데이터가 변경되면 개발자가 DOM 요소를 직접 찾아 수정
    - ex) 좋아요 버튼
        
        ```jsx
        let likeCount = 0;
        
        button.addEventListener("click", () => {
          likeCount += 1;
        
          document.querySelector("#like-count").textContent = likeCount;
        });
        ```
        
    - 개발자가 다음 과정을 모두 작성해야 함.
        - 사용자 클릭 → 데이터 변경 → 변경할 DOM 탐색 → DOM의 값 직접 수정
    - 기능이 많아지면
        - 수정해야 할 DOM 요소가 많아짐.
        - 데이터와 화면을 각각 관리해야 함.
        - 어떤 데이터가 어떤 화면을 바꾸는지 추적하기 어려워짐.
        - 비슷한 UI와 DOM 조작 코드가 반복됨.
        - …
3. **React의 해결 방법**
    - React는 개발자가 DOM을 직접 변경하는 대신, 현재 데이터에 따라 화면이 어떻게 보여야 하는지 작성하도록 함.
        
        ```jsx
        <button>좋아요 {likeCount}</button>
        ```
        
    - `likeCount`가 변경되면 React가 새로운 데이터에 맞게 화면을 갱신
    - **이처럼 화면을 변경하는 세부 명령을 작성하지 않고, 원하는 화면의 모습을 작성하는 방식
    ⇒ 선언형 UI**

### 5. 컴포넌트

- React가 데이터에 따라 화면을 갱신해주더라도, SNS 전체 화면을 하나의 코드로 작성하면 여전히 복잡함.
- SNS는 `헤더`, `사용자 프로필`, `게시글`, `좋아요 버튼`, `댓글`처럼 여러 UI로 구성됨.
- **React는 이러한 화면을 작은 단위로 나누어 관리 ⇒ 컴포넌트**
- **컴포넌트**
    - 화면을 구성하는 독립적이고 재사용 가능한 UI 단위
- ex) 좋아요 버튼을 하나의 컴포넌트로
    
    ```jsx
    function LikeButton() {
      return <button>좋아요</button>;
    }
    ```
    
- ex) 게시글도 별도의 컴포넌트로
    
    ```jsx
    function PostCard() {
      return (
        <article>
          <h2>미영</h2>
          <p>React를 공부했습니다.</p>
          <LikeButton />
        </article>
      );
    }
    ```
    
    - `PostCard` 안에서 `LikeButton`을 일반 HTML 태그처럼 사용할 수 있음.
    
    ```jsx
    PostCard
     ├── 사용자 이름
     ├── 게시글 내용
     └── LikeButton
    ```
    

### 6. 컴포넌트의 장점

1. **재사용성**
    - 한 번 만든 컴포넌트를 여러 곳에서 사용할 수 있음.
2. **유지보수성**
    - 좋아요 버튼을 수정해야 한다면 `LikeButton` 컴포넌트만 수정하면 됨.
3. **역할 분리**
    - 화면을 기능별로 나누기 때문에 각 코드가 어떤 역할을 담당하는지 쉽게 파악할 수 있음.

### 7. JSX

- JavaScript 안에서 HTML과 비슷한 형태로 UI를 작성할 수 있게 해주는 문법

```jsx
<h1>Hello</h1>
```

```jsx
React.createElement("h1", null, "Hello");
```

- **컴포넌트와 JSX의 관계**
    - 컴포넌트 : 화면을 나누는 단위
    - JSX : 컴포넌트의 화면 구조를 작성하는 문법

### 8. Props와 State

1. **컴포넌트마다 다른 데이터를 보여주려면?**
    - `PostCard` 컴포넌트를 만들어서 여러 번 재사용함.
        
        ```jsx
        <PostCard />
        <PostCard />
        <PostCard />
        ```
        
    - 하지만 모든 게시글에 같은 사용자와 같은 내용을 보여주면 안 됨.
    - **컴포넌트의 구조는 재사용하면서 게시글마다 서로 다른 데이터를 넣어줘야 함.
    ⇒ Props**

1. **Props**
    - 부모 컴포넌트가 자식 컴포넌트에 전달하는 데이터
    - 같은 컴포넌트에 서로 다른 Props를 전달하면 게시글마다 다른 내용을 보여줄 수 있음.
        
        ```jsx
        <PostCard
          username="미영"
          content="React를 공부했습니다."
        />
        
        <PostCard
          username="민수"
          content="데이터베이스를 공부했습니다."
        />
        ```
        
    - `PostCard`는 전달받은 Props를 다음과 같이 사용함.
        
        ```jsx
        function PostCard({ username, content }) {
          return (
            <article>
              <h2>{username}</h2>
              <p>{content}</p>
            </article>
          );
        }
        ```
        
    - Props는 부모가 전달한 값이므로 자식 컴포넌트에서 직접 변경할 수 없음.

1. **화면에서 변경되는 값은 어떻게 관리?**
    - 사용자 이름과 게시글 내용은 부모에게 전달받을 수 있음.
    - 하지만 좋아요 수는 사용자가 버튼을 클릭할 때마다 변경됨.
    - **컴포넌트가 기억하고 관리해야 하는 변경 가능한 데이터 ⇒ State**
    
    ```jsx
    function LikeButton() { // <- 함수 컴포넌트 : 함수 형태로 만든 React 컴포넌트
      const [likeCount, setLikeCount] = useState(0);
      // 0은 likeCount에만 들어가고, setLikeCount는 상태변경함수, 0이 할당되는 건 아님.
    
      return (
        <button onClick={() => setLikeCount(likeCount + 1)}>
          좋아요 {likeCount}
        </button>
      );
    }
    ```
    
    - `likeCount` : 현재 State 값
    - `setLikeCount` : State를 변경하는 함수
    - `0` : State의 초깃값
    - `useState`  : 함수 컴포넌트에서 State를 사용할 수 있게 해주는 React Hook
        - **React Hook**
            - 함수 컴포넌트에서 React의 여러 기능을 사용할 수 있게 해주는 함수
        - **대표적인 Hook**
            
            
            | Hook | 역할 |
            | --- | --- |
            | `useState` | 컴포넌트의 상태 관리 |
            | `useEffect` | 외부 시스템과 동기화 |
            | `useRef` | DOM 요소나 값을 참조 |
            | `useContext` | 여러 컴포넌트가 공유하는 데이터 사용 |
    - **State를 다음과 같이 직접 변경하면 React가 상태 변화를 정상적으로 처리할 수 없음.**
        
        ```jsx
        likeCount = likeCount + 1;
        ```
        
    - **State는 반드시 상태 변경 함수를 이용해 변경해야 함.**
        
        ```jsx
        setLikeCount(likeCount + 1);
        ```
        

### 9. 단방향 데이터 흐름

1. **부모 컴포넌트와 자식 컴포넌트**
    
    ```jsx
    function App() { // <- 부모 컴포넌트
      return <PostCard />; // <- 자식 컴포넌트 
    }
    ```
    
2. **데이터는 부모에서 자식으로 전달된다**
    
    ```jsx
    function App() {
      const [likeCount, setLikeCount] = useState(0);
    
      return <PostCard likeCount={likeCount} />;
    }
    
    function PostCard({ likeCount }) {
      return <button>좋아요 {likeCount}</button>;
    }
    ```
    
    - **데이터의 흐름**
        
        ```jsx
        App의 likeCount
               ↓ Props
        PostCard의 likeCount // 직접 변경 불가
        ```
        
3. **자식에서 데이터를 변경하려면?**
    - 부모는 State와 함께 State를 변경할 수 있는 함수를 자식에게 전달
        
        ```jsx
        function App() {
          const [likeCount, setLikeCount] = useState(0);
        
          return (
            <PostCard
              likeCount={likeCount}
              onLike={() => setLikeCount(likeCount + 1)} 
            />
          );
        }
        ```
        
    - 자식은 전달받은 함수를 버튼에 연결
        
        ```jsx
        function PostCard({ likeCount, onLike }) {
          return (
            <button onClick={onLike}>
              좋아요 {likeCount}
            </button>
          );
        }
        ```
        
    - **데이터 흐름**
        - 부모가 State와 함수를 자식에게 전달
        → 자식에서 버튼 클릭
        → 자식이 부모에게 받은 함수 실행
        → 부모의 State 변경
        → 변경된 State가 다시 자식에게 전달
    - **자식이 부모의 State를 직접 변경한 게 아님.
    부모에게 전달받은 함수를 실행하여 부모가 자신의 State를 변경하도록 요청**
4. **왜 단방향 데이터 흐름을 사용하는가?**
    - 데이터의 출처를 파악하기 쉬움.
    - State가 변경된 위치를 찾기 쉬움.
    - 애플리케이션의 동작 예측 쉬움.

### 10. 리렌더링과 Virtual DOM

- **렌더링**
    - React가 컴포넌트를 실행하여 화면에 어떤 UI를 보여줄지 계산하는 과정
    
    ```jsx
    function LikeButton() {
      const [likeCount, setLikeCount] = useState(0);
      // 처음 실행하면 likeCount가 0이므로
    
      return <button>좋아요 {likeCount}</button>;
      // UI는 <button>좋아요 0</button>이 됨. => 초기 렌더링
    }
    ```
    
- **리렌더링**
    - 사용자가 버튼을 클릭하여 State를 변경했다고 가정.
    - **React는 State가 변경되었다는 것을 인식하고 `LikeButton` 컴포넌트를 다시 실행 ⇒ 리렌더링**
    - 실제 화면을 새로 만드는 게 아니라, 변경된 State를 기준으로 새로운 UI를 계산하는 과정
- **Virtual DOM**
    - React는 컴포넌트가 반환한 UI 구조를 메모리상의 JavaScript 객체로 표현
    - 좋아요 수가 변경되면 다음 두 결과가 만들어짐.
        
        ```jsx
        이전 Virtual DOM: <button>좋아요 0</button>
        새 Virtual DOM:   <button>좋아요 1</button>
        ```
        
    - React는 두 결과를 비교하여 좋아요 숫자만 변경되었다는 것을 파악
    - **이후 실제 DOM 전체를 새로 만드는 것이 아니라 변경된 텍스트만 수정
    ⇒ Reconciliation, 재조정**
        - 이전 렌더링 결과와 새로운 렌더링 결과를 비교하여 실제 DOM에 어떤 변경이 필요한지 결정하는 과정

### 11. React.memo

- 부모 컴포넌트가 리렌더링되면 일반적으로 부모가 포함하고 있는 자식 컴포넌트도 다시 실행됨.
- **`React.memo`**
    - **컴포넌트가 전달받은 Props가 이전과 같다면 기존 렌더링 결과를 재사용하도록 도와주는 최적화 기능**

```jsx
const Profile = React.memo(function Profile({ username }) {
  return <h2>{username}</h2>;
});
```

- 좋아요 수가 변경되어 `App`이 리렌더링되더라도 `Profile`의 `username`이 그대로라면 `Profile` 의 리렌더링을 건너뛸 수 있음.
- **리렌더링 전에 이전 Props와 새로운 Props를 비교해야 한다. 이 비교 작업에도 비용이 발생
⇒ 모든 컴포넌트에 사용하는 것은 오히려 불필요한 작업을 늘릴 수 있음.**

### 12. Next.js

- React는 UI 구현에 집중하는 라이브러리이기 때문에 이러한 기능을 모두 기본으로 제공하지 않음.
- 필요한 기능은 개발자가 다른 라이브러리를 선택하여 직접 구성해야 함.
- **Next.js**
    - **React를 기반으로 웹 애플리케이션을 만들기 위한 프레임워크**
    - React의 컴포넌트와 State 같은 기능을 그대로 사용하면서, 완성된 웹 애플리케이션을 만드는 데 필요한 기능을 추가로 제공

### 13. 다른 기술과의 비교

| 기술 | 분류 | 특징 |
| --- | --- | --- |
| React | UI 라이브러리 | UI 구현에 집중하며 필요한 기능을 추가로 선택 |
| Vue | 점진적 프레임워크 | 비교적 문법이 직관적이고 필요한 만큼 도입 가능 |
| Angular | 프레임워크 | 라우팅, HTTP 통신 등 다양한 기능을 기본 제공 |
| Svelte | UI 프레임워크·컴파일러 | 빌드할 때 코드를 변환하여 동작 |
| SolidJS | UI 라이브러리 | React와 문법이 유사하지만 상태 변경 처리 방식이 다름 |
| Preact | UI 라이브러리 | React와 유사하면서 크기가 가벼움 |
