서버의 기본적인 개념과 웹 서버, WAS의 동작을 정리

# 서버
사용자(클라이언트)의 요청을 받아 그에 맞는 정보나 데이터를 제공하는 컴퓨터 또는 프로그램.

# 웹 서버
HTTP/HTTPS 요청을 처리하는 서버.
클라이언트의 요청을 받아 HTML, 이미지, CSS 같은 정적 콘텐츠를 전달함.

대표적으로 Apache, Nginx가 있음.

### 배경
초기 웹은 문서를 공유하기 위한 시스템에 가까웠음.
단순 문서 공유는 프로그램 실행이 필요 없고 해당 파일을 전달하기만 하면 됨. 

그러나 로그인처럼 데이터베이스를 조회해야 하는 상황이 생기며 동적인 콘텐츠 생성이 필요해짐. 이를 처리하는 게 WAS!

웹 서버가 WAS에 요청을 전달함. 이게 바로 **리버스 프록시**! 사용자가 직접 WAS에 요청할 필요 없음.


### Web 서버의 주요 역할
- 정적 파일 처리
- 요청을 WAS나 다른 서버로 전달
- 보안 처리
- 로드 밸런싱

# WAS
Web Application Server
프로그램을 실행하고 동적인 결과를 만들어 사용자에게 전달하는 서버.

대표적인 WAS로는 아파치 톰캣이 있음.

실제 시스템 예시

사용자가 쇼핑몰에서 A 상품 정보를 조회하고 싶다면
```
사용자 브라우저 -> 웹 서버 -> WAS -> 데이터베이스
```
1. 브라우저가 웹 서버에 요청
2. 웹 서버가 요청을 분석
3. 정적 파일은 웹 서버가 처리, 상품 정보를 조회하기 위해 프로그램 실행이 필요하므로 해당 요청을 WAS로 전달 
4. WAS가 데이터베이스에서 상품 정보를 조회
5. HTML 또는 JSON을 생성해 웹 서버로 전달
6. 웹 서버가 브라우저에 응답


# 정리
- 웹 서버와 WAS는 역할을 나누어 함께 사용하는 경우가 많음. 
- 웹 서버는 클라이언트 요청을 먼저 받아 정적 자원을 처리하고 동적 요청은 WAS로 전달. 서버 부하 줄이고 성능 향상!
- WAS를 노출시키지 않고 웹 서버 뒤에 두어 보안성 지킴.
- 웹 서버가 요청을 분산 처리하므로 WAS를 여러 대 늘리기 쉬움(확장성)
- WAS에 문제가 생겨도 웹 서버가 정적 페이지 제공 가능 (장애 격리)
